[glass-LIO](https://github.com/Tim-HW/glass-lio) is a transparent LiDAR-inertial odometry stack for the **Livox MID-360**, targeting **ROS 2 Jazzy**. Most SLAM code is written to run; this one is written to be **understood** — scan-to-map odometry with deskew, voxel-plane mapping, and point-to-plane ICP solved by Gauss-Newton on SE(3), with every non-obvious decision documented, including the ones that turned out to be wrong.

---

## What it does

A Livox scan is a ~100 ms sweep, not a snapshot. glass-LIO integrates the gyro on SO(3) to deskew each sweep, voxel-downsamples it, registers it against a voxel-hash local map, then inserts the aligned scan back into that map. Output is `/glasslio_node/odom` (`nav_msgs/Odometry`) plus TF — no ground truth, no loop closure. On the bundled test bag it holds real time at 10 Hz with zero dropped scans.

---

## Why it's worth a look

- **Stage-by-stage write-ups** — six pipeline docs plus the solver, in execution order, explaining the traps each stage sets rather than just the code it runs.
- **Bugs documented, not hidden** — including failures that still produce plausible output (sign-flipped Jacobians, silently wrong plane fits).
- **No Ceres, GTSAM, or g2o** — the manifold least-squares solver is pure Eigen and meant to be read alongside `gauss_newton.hpp`.
- **Tests as oracles** — finite-difference checks pin every Jacobian; mutation testing verifies the tests would actually notice regressions.
- **One-command quickstart** — Docker, devcontainer, or native Jazzy build paths, with a checksum-verified test bag fetched from Zenodo (~1.4 GB).

If you care about the math more than the sensor stack, `glass_core/` is pure CMake (no ROS, no PCL) — build it and run `ctest` to walk through the Gauss-Newton and preintegration checks as worked examples.
